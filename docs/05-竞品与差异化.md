# 05 · 竞品与差异化

## 横向对比

| 方案 | 代表 | 强项 | 在执法合规场景的短板 |
|---|---|---|---|
| 通用大模型对话 | ChatGPT / 文心 / 通义 | 上手零门槛、表达流畅 | 法条幻觉、无审计痕迹、信息不足硬答、责任不可追溯 |
| 法律垂类助手 | 得理、法智汇等法律检索/咨询产品 | 法条库全、检索准 | 面向"查法条/咨询"，不面向"处罚决定前的合规自查"这一工作流 |
| 执法办案系统自带校验 | 各地办案平台内嵌的文书校对 | 与办案流程一体化 | 校验多为**格式级**（错字、缺项），极少做实体与裁量层审查 |
| 规则引擎产品 | Drools 等通用规则引擎 | 引擎成熟 | 与法律知识无关：谁来写规则、怎么保证规则本身对，仍是空白 |
| 低代码审查工具 | 本项目早期原型 | 快速验证了规则数字化可行性 | 无评测、无置信分级、无降级设计，结论不可追溯 |

## 度衡的五个差异点

1. **判定权与表达权分离**——LLM 只读文书、写文书；判定在规则层，可审计。
   这是与"大模型直接审"路线的根本分野。
2. **三值逻辑 + 待核实清单**——不确定性是一等公民，不是被吞掉的 False。
3. **依据置信分级**——法条依据分 high/medium，不确定的条文号在界面上明示。
   法律 AI 的幻觉无法根治，但可以被标注、被拦截、被人工兜底。
4. **评测先行**——干净集 + 压力集双轨，敢把压力集 50% 的结论一致率写在 README 里。
   多数同类宣传只展示成功案例。
5. **留痕优先**——规则版本、地区参数档、推定字段、命中规则、指纹随结果返回，
   目标形态是"审查留痕可以直接进案卷"。

## 护城河的真实评估（不自欺）

- **不构成护城河**：规则本身（26 条要点）可被复制；界面无壁垒；正则抽取无壁垒。
- **可能构成护城河**：
  - **评测集**——真实案卷构造的脏数据集需要执法单位合作，拿到就是壁垒；
  - **规则维护机制**——法条修订时的规则更新流程与责任分配，是组织能力不是技术；
  - **领域判断**——知道"哪些事由在复议诉讼里真的会输"，这来自案卷复盘而非法条阅读。
- 结论：这个开源仓库展示的是**方法与判断**，壁垒要在与执法单位的合作里长出来。
  把这句写进 README，是因为 AI 产品经理的诚实比宣传更值钱。

## 如果有一天要商业化

- 切入点：法制审核环节的"案卷预检"，按案卷数订阅；
- 交付形态：本地化部署（执法数据不出域），规则库支持属地化配置；
- 合规前提：与执法单位合作取得脱敏案卷授权，评测集与规则更新共同维护。
